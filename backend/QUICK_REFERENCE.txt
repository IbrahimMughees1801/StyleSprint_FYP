# QUICK REFERENCE - Full ML Virtual Try-On

Use this for evaluation/demo. Do not start `api_server_simple.py`.

## 1. Start the full ML backend

Open PowerShell from anywhere and run:

```powershell
cd C:\Users\muhdi\Desktop\fyp_app\backend
$env:API_PROCESSING_MODE='ml'
$env:API_FALLBACK_TO_SIMPLE='false'
..\.venv\Scripts\python.exe -m uvicorn api_server:app --host 0.0.0.0 --port 8000
```

Keep this terminal open.

Check locally:

```powershell
Invoke-WebRequest http://127.0.0.1:8000/api/tryon/readiness -UseBasicParsing
```

Expected important values:

```text
"configured_mode":"ml"
"active_mode":"ml"
"ml_stack_ready":true
```

## 2. Start the public phone tunnel

Open a second PowerShell window:

```powershell
& "C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://localhost:8000
```

Cloudflare will print a URL like:

```text
https://something-random.trycloudflare.com
```

Keep this terminal open too.

Important:

- Each new quick tunnel usually creates a new URL.
- If the tunnel is closed and reopened, update the Flutter command with the new URL.
- The phone and laptop do not need the same WiFi, but both need internet.

Test the tunnel in your phone browser:

```text
https://YOUR-TUNNEL.trycloudflare.com/api/tryon/readiness
```

It should show `active_mode` as `ml`.

## 3. Run Flutter on the phone

Open a third PowerShell window from the project root:

```powershell
cd C:\Users\muhdi\Desktop\fyp_app
flutter run --dart-define=TRYON_API_BASE_URL=https://YOUR-TUNNEL.trycloudflare.com
```

Use the exact URL printed by Cloudflare.

Do a full rerun after changing the tunnel URL. Hot reload is not enough for `--dart-define`.

## 4. Expected app behavior

The full ML pipeline is slow because it runs:

YOLO -> FastSAM -> DensePose -> OpenPose -> Graphonomy -> PF-AFN -> DCI-VTON

The app now handles this asynchronously:

1. Start try-on.
2. App says the try-on is processing in the background.
3. Continue browsing the app.
4. When processing finishes, the app prompts that the try-on is ready.
5. Open Profile -> Saved Try-ons to view the result.

This is the intended demo flow for the full model.

## 6. Stop everything

To stop backend and tunnel:

```powershell
Get-Process python,cloudflared -ErrorAction SilentlyContinue | Select-Object ProcessName,Id,StartTime,Path
```

Then stop the listed backend/tunnel processes:

```powershell
Stop-Process -Id YOUR_PROCESS_IDS -Force
```

Check port 8000 is free:

```powershell
Test-NetConnection -ComputerName 127.0.0.1 -Port 8000
```

Expected when stopped:

```text
TcpTestSucceeded : False
```

## 7. Common issues

### Port 8000 already in use

This means the backend is already running, or an old process is still using the port.

```powershell
Get-Process python -ErrorAction SilentlyContinue | Select-Object Id,StartTime,Path
```

Stop the old backend process, then restart the full ML backend.

### Phone says backend is not running

Check these in order:

1. Backend terminal is still open.
2. Tunnel terminal is still open.
3. Flutter was run with the current Cloudflare URL.
4. Phone browser can open:

```text
https://YOUR-TUNNEL.trycloudflare.com/api/tryon/readiness
```

### Old tunnel URL stopped working

That is normal for quick tunnels. Restart cloudflared, copy the new URL, and rerun Flutter with the new `--dart-define`.

### Try-on takes several minutes

That is expected for the full ML stack. The result should appear in Profile -> Saved Try-ons when complete.
